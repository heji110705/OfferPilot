# OfferPilot · 网申领航

面向 2027 届校招的 **AI 网申浏览器扩展**：把「档案 → 简历 → 岗位 → 网申表单 → 投递进度」串成一条链。打开招聘页时先认出你在投哪个岗位，自动挑出简历库里最贴的那一版，再用它一键写入（也可只填框选区域、或逐项辅助补全）；挑好的多个岗位还能交给队列，在浏览器里逐个打开官网自动填，遇到档案没有的字段停下来问你，人只做最后复核与提交。

参考产品：[cv.playoffer.cn（来个简历闪填）](https://cv.playoffer.cn/)、[锦鲤求职](https://jinliqiuzhi.com/)（岗位大厅 + 批量网申，见 §3.8）
运行形式：**Chrome / Edge 扩展（Manifest V3）**，另保留纯网页形态用于预览演示。

## 一、参考产品拆解

参考产品本质是一个**浏览器插件**：不改变企业官网，只在表单页面上"代填"。链路是：

```
安装插件 → 完善简历（多份）→ 打开企业网申页 → 识别字段
→ 语义匹配 → 一键写入 → 缺失项提醒 → 人工复核 → 自己点提交 → 记录投递
```

拆出 6 个模块：档案/简历中心、字段语义识别、一键填充、缺失项与支持度、AI 辅助、投递记录。

它的空档是**投前与投后**：没有 JD 驱动的版本定制、没有笔试/面试/Offer 流程跟踪、没有材料版本管理。本工具在这三点上补齐，形成 6 个页面：

| 页面 | 解决的问题 | 关键交互 |
|------|-----------|---------|
| 工作台 | 今天该干什么 | AI 待办（按截止时间 + 流程状态排序）、队列提醒条、投递漏斗、完整度 |
| 我的档案 | 信息填一次，到处复用 | 5 个分区、完整度环形进度、从简历文本导入、AI 诊断 |
| 简历库 | 一份简历投所有公司是减分项 | 多版本、A4 实时预览、按 JD 定制、导出 / 打印 |
| 岗位大厅 | 岗位散落在几十个官网 | 40 个内置岗位 + 手动导入、按匹配度 / 截止排序、收藏、勾选批量投递 |
| 自动网申 | 一份份填表太慢 | 队列串行打开官网 → 自动填写 → 缺字段追问 → 逐个完成，可接管可重试 |
| 网申填写 | 表单太长、字段太多 | **真实页面识别 + 一键填充**、支持度、缺项提醒、复核 |
| 投递进度 | 投了十几家记不清 | 六阶段看板、拖拽改状态、时间线、备注 |
| 岗位情报 | 不知道机会集中在哪 | 行业 / 城市分布、7 天截止预警、按简历库匹配的机会榜 |
| AI 助手 | 不会写开放题 | JD 匹配、简历定制、自我介绍、STAR 润色、面试预测 |

## 二、为什么原方案不能直接跑在浏览器里

原方案是一个**单页 Web 应用**：它渲染自己定义的网申表单，填充就是给 `data-key` 输入框赋值。这套逻辑放到浏览器里，有六个绕不过去的障碍——**前五个是平台的，第六个是认知的**：

| # | 障碍 | 具体表现 | 后果 |
|---|------|---------|------|
| 1 | **同源策略** | 页面脚本只能访问**自身 origin** 的 DOM。你的工作台在 `localhost`/静态站，表单在 `jobs.bytedance.com`，两者是不同源 | 网页版**永远读不到也写不进**企业官网的表单。这是最根本的原因，与代码质量无关，靠前端技巧无法绕过 |
| 2 | **没有宿主生命周期** | 普通页面随标签页关闭而消失，没有常驻后台 | 无法做「用户打开任意招聘页时响应工具栏点击 / 快捷键 / 右键菜单」这类跨站点、跨标签的响应 |
| 3 | **存储按 origin 隔离** | `localStorage` 绑定在单一 origin 上，`file://`、`localhost`、企业域名三者互不相通 | 档案无法做到「一处填写、全站可用」；换个入口数据就没了 |
| 4 | **无注入能力与浏览器级入口** | 页面脚本不能向其他站点注入代码，也没有图标、徽标、右键菜单 | 用户必须"先打开工作台再回到官网"，中间没有连接点 |
| 5 | **跨域请求受限** | 浏览器按 CORS 判定，任意自建 LLM 端点会被拦 | 远程模型只能走允许 CORS 的服务；换成自建网关就失效 |
| 6 | **模拟表单 ≠ 真实表单** | 原 `apply.js` 里的表单是**自己写的**：字段 id 已知、结构固定、`document.querySelector('[data-key="phone"]')` 必然命中。真实页面呢？北森用 `table` + `th` 布局，Moka 用 `div.form-item`，大厂自建站用 Ant Design 的受控组件，字段名是 `candidateName` / `mobilePhone` / `emergencyPhone` 这种不带语义的英文 | 填充从"赋值"变成了**先猜字段、再写值、还要让 React/Vue 认账**三件事 |

第 6 点最容易被低估：它不是"能不能跑"的问题，而是"跑了有没有用"。直接 `el.value = x` 在受控组件里会被下一次 render 抹掉；`紧急联系人电话` 会被朴素关键词匹配成 `手机号码`——**填错比不填更糟**。

扩展恰好能消除前五个（`content_scripts` 注入、`service_worker` 常驻、`chrome.storage` 跨源、`host_permissions` 免 CORS、`action`/`commands`/`contextMenus` 提供入口），所以改造的重点实际落在第 6 点：**重写一个能对付未知 DOM 的识别与写入引擎**。

消息协议（全部以 `OP_` 前缀隔离，避免与页面脚本冲突）：

| 方向 | 消息 | 用途 |
|------|------|------|
| content → SW | `OP_REPORT` | 每帧上报识别结果，SW 按 `tabId` 聚合 |
| SW → content | `OP_FILL` `OP_SCAN` `OP_UNDO` `OP_TOGGLE` | 执行填充 / 重扫 / 撤销 / 展开浮层 |
| 弹窗·工作台 → SW | `OP_GET_REPORT` `OP_FILL_TAB` `OP_SCAN_TAB` `OP_UNDO_TAB` `OP_STATE_CHANGED` | 查询与操作指定标签页；档案变更后通知全站重扫 |
| content → SW | `OP_OPEN_APP` | 浮层里的「打开工作台」 |

用 SW 中转而不是直连 content script，是因为一份网申可能跨 iframe（北森/Moka 都有）。**每个 frame 各自识别、各自上报，SW 合并出总数**；填充时广播到所有 frame，各填各的。

### 3.2 识别引擎怎么工作

以真实页面为例，一个 `<input>` 要经过四步才变成"姓名"：

1. **找标签**——按可靠性排序：`el.labels` → `aria-label` / `aria-labelledby` → 所在 `.form-item` 内的 `label` → 向上 5 层找"紧邻的短文本"（覆盖 `table` 的 `th` 与 `div` 布局）→ `placeholder` / `title` / `name` / `id` 兜底。
2. **分词打分**——`camelCase` 拆词（`candidateName` → `candidate name`）、全角转半角、去标点；中文按子串命中，英文按词边界命中。命中越长的关键词得分越高。
3. **反例拦截**——每个字段带 `neg` 词表：`手机号码` 拒绝 `紧急/父亲/家长/推荐人/验证码`，`姓名` 拒绝 `用户名/公司名/英文名`，`所学专业` 拒绝 `专业排名/专业技能`。**这一层决定了它敢不敢用在真实投递上。**
4. **去重与排序**——同一字段只取页面上第一个，列表按文档顺序还原，和用户看到的表单顺序一致。

写入时避开框架的坑：

```js
// 直接 el.value = x 会被 React 的受控组件抹掉
const proto = el.tagName === 'TEXTAREA' ? HTMLTextAreaElement.prototype : HTMLInputElement.prototype;
Object.getOwnPropertyDescriptor(proto, 'value').set.call(el, value);  // 绕过 React 的 value tracker
el.dispatchEvent(new Event('input',  { bubbles: true }));
el.dispatchEvent(new Event('change', { bubbles: true }));
// 写完回读一次，被前端校验清空的字段会如实报告"写入后被页面清空"
```

下拉与单选不是赋值，而是**选项匹配**（细节见 §3.2.1），匹配不上就跳过并说明原因（`下拉里没有「本科」（共 4 个选项）`），绝不硬塞第一个选项。日期按月/日类型自动补齐（`2027-06` → `2027-06-01`），数字框里的 `3.62 / 4.0` 只取 `3.62`。

#### 3.2.1 枚举选项：把「本科」填进「本科（学士）」

同一份档案，页面上的写法千差万别。原来只有「精确 → 前缀 → 包含」三级文本比较，于是：

| 页面上的选项 | 档案里的值 | 旧逻辑结果 |
|------------|-----------|-----------|
| `本科（学士）` | 本科 | 前缀能中，但 `本科以下` 也会中 |
| `大学本科` | 本科 | 能中（包含），但优先级低于「本科以下」的前缀命中 |
| `3. 本科` | 本科 | **选不中**（序号在前，前缀不匹配） |
| `男性` | 男 | **选不中**（包含匹配被 `n.length > 1` 挡掉） |
| `中国·居民身份证` | 居民身份证 | 能中（包含） |
| `同意` / `不同意` | 是 | **两条都中前缀**，可能选中「不同意」 |

现在把这件事交给 `assets/js/optionmap.js`，三层处理：

1. **归一化 `base()`**——去括号补充（`本科（学士）` → `本科`）、去序号（`3. 本科` → `本科`、`① 男` → `男`）、全角转半角、去分隔符（`中国·居民身份证` → `中国居民身份证`）。
2. **同义词组**——每组第一项是档案标准值，后面是各站点的等价写法：`男 ↔ 男性/男生/male/M`、`本科 ↔ 大学本科/本科生/学士/bachelor`、`居民身份证 ↔ 身份证/二代身份证/中华人民共和国居民身份证`、`是 ↔ 同意/接受/愿意/服从`、`否 ↔ 不同意/不接受`……覆盖性别、学历、学位、政治面貌、民族、证件类型、婚姻、户口性质、学习形式、工作状态、工作年限、是/否、健康状况 13 组。
3. **打分**——完全相等 100、同义词 97、选项以值开头 92、值以选项开头 88、包含 74；再叠三条硬规则：

   - 单字值（男 / 女 / 汉）**只认同字**，否则「男女不限」会被选中；
   - 选项以 `不 / 非 / 未 / 无` 开头时不与肯定值互相匹配，否则「不同意」会被当成「同意」；
   - 含「以上」乘 0.75（本科满足「本科及以上」），含「以下 / 不含」乘 0.45（不能拿本科去填「本科以下」）；低于 56 分直接放弃，宁可空着也不瞎选。

**级联下拉**（「所在地点」这类省 / 市 / 区）走另一条路径：`steps('广东省湛江市') → ['广东省','湛江市']`，先选省 → 等 180ms 让下一级重新渲染 → 找同一块表单里的下一个 `select` → 选市。如果页面其实只有一个下拉、选项是「广东省-湛江市」合并的，第一级就会整串命中，下一级为空自然停下。

**三条填写入口共用同一条链路**：`applyItems()` 把所有 `select` 与 `selectx` 排进同一个串行队列（两个下拉同时点开会互相把对方关掉），一键填写、选区填写、辅助填写都走它；写入成功照样进 `undoStack`、照样加蓝框、照样计入结果卡，只是多记一条 `下拉 N 项已选中`。

**自定义下拉（Moka / 北森 / antd / arco / element）是另一套识别逻辑**，也是最容易"看起来识别不到"的地方：

| 阶段 | 做法 |
|------|------|
| 识别 | 这类控件的内核是一个 `readonly` 的 `<input>`，或干脆只有一个纯 `div`。旧逻辑遇到 `readOnly` 直接跳过，于是「性别」「招聘信息来源」「是否服从调剂」整片消失。现在先判断它是不是在下拉容器（`.ant-select` / `.arco-select` / `.el-select` / `[role=combobox]`）里，是就单独登记为 `selectx` |
| 找标签 | 容器上没有 `label`，从 `.ant-form-item-label` 取；站点没有标准 form-item 时，向上三层找"自己不包含表单控件"的那个 `label`；再退到占位文案 |
| 写入 | 点开 → 轮询等下拉挂载（最多 800ms）→ 在 `.ant-select-item-option` / `[role=option]` 里按文本匹配 → 派发 `mousedown/mouseup/click` → 回读 `.ant-select-selection-item` 校验 |
| 判空 | 读的是选中项节点，不是 `input.value`（它是空的），所以"已有内容不覆盖"对这类控件同样成立 |

### 3.3 存储与状态

```
写：Store.setProfile() → emit() → ①localStorage 镜像（同步，保证刷新秒开）
                                → ②chrome.storage.local（节流 300ms）
读：boot() → Store.init()（读镜像，首屏立即渲染）
          → Store.hydrate()（读 chrome.storage，与镜像不同则替换并重绘）
同步：chrome.storage.onChanged → Store.replace()（比较 JSON，相同则不重绘，避免回环）
```

### 3.4 简历 PDF 解析（简历库 → 上传简历 PDF）

四段链路，每段单独可测：

```
PDF 字节
 → pdftext.js     对象扫描（含对象流 / 损坏 xref）→ Flate 解压 → ToUnicode CMap → 按坐标归行
 → resumeparse.js 章节切分 → 字段抽取（专业/学历/时间/GPA）→ 项目切条 → 校验告警
 → importflow.js  逐项预览（可就地修改）→ 勾选要保留的项目 → 写入
 → store.js       以简历为唯一事实来源整体替换经历 + 生成新版本
```

几个关键决定：

- **为什么不用 pdf.js**：MV3 页面不能加载远程脚本，运行环境也没有外网。`pdftext.js` 自己实现对象扫描、对象流展开、Flate（`DecompressionStream`）、ToUnicode CMap 与文本矩阵还原，零依赖、离线可用。
- **先还原行结构**：PDF 里每个字都是独立绘制的，直接拼字符会把 `SHEIN` 拼成 `SH EIN`。解析时维护 `q / Q / cm / Tm / Td` 的变换矩阵，按设备坐标归行，只有视觉间距超过 0.55 em 才补空格；同时按 CTM 的 y 方向决定"从上到下"的阅读顺序。
- **专业走词典最长匹配**：`数据科学与大数据技术` 排在 `数据科学` 之前，命中取最长词；词典没覆盖时只取原文的「XX专业 / 专业：XX」，**绝不猜近义词**。这是"数据科学与大数据技术"不会被写成"计算机科学与技术"的原因。
- **小标题必须先剥序号**：中文简历常写成 `01 专业技能` / `02 教育背景` / `03 项目经历`。`compact()` 之后是 `01项目经历`，如果只按「数字 + 标点」剥序号就会全部漏掉，**一个栏目都切不出来**，整份简历退化成一坨正文（这也是"项目经历 0 个"最常见的真因）。现在支持 `01` `1.` `一、` `（一）` `第X部分` `PART 1` 以及尾部计数 `项目经历（3）`；实在认不出时还有一层「关键词宽松兜底」，并要求关键词 ≥3 字，避免「项目 / 教育」这类短词乱命中。
- **项目切条不只看时间**：很多简历的项目标题**不带日期**（时间只写在教育栏）。只认「标题 + 时间」会把条目全部丢掉。现在的判定是多信号的：下一行是 `技术栈：` 这类元信息、下一行是项目符号、标题以「独立开发 / 课程项目 / 负责人」收尾、标题里有 `·` 分隔符，任一成立即视为新条目；同时排除「上一行以逗号收尾」（说明是折行续写）和「算法负责人」这类纯角色行。
- **`·` 是连接符不是分隔符**：`豆瓣电影 · 电影数据采集分析与可视化大屏` 里的 `·` 属于项目名，不能用来切角色，否则会把名字切成 `Douban Movie`、把副标题当成职务。角色只从全角空格 / `|` 之后取，并且要命中职务词表。
- **元信息行归位**：`技术栈：…` `项目描述：…` `项目职责：…` `项目成果：…` 不再混进职责条目，分别落到 tech / desc / duties / results 字段（技术栈并入「项目描述」首行展示）。
- **项目符号要认得全**：`▸ ▶ ► ✓` 这些箭头类符号此前不在符号表里，整段职责都不算「条目行」；另外「16.6%」曾被 `\d{1,2}[.]` 当成编号吃掉前两位变成「6%」，现在数字序号要求后面不是数字。
- **每行都要有归属**：章节内的行要么成为标题、角色、职责，要么计入「未归属」；识别报告给出覆盖率与逐条告警（缺名称 / 缺时间 / 缺职责），不静默丢弃。

边界：只处理**文字版 PDF**，扫描件会明确提示"几乎没有可提取的文字"；文件不落盘，解析在内存完成。

浮层同样遵守「不自动提交」：所有写入都止步于表单内容，提交按钮永远由人点。

**「缺失字段」是怎么算出来的**：`analyze()` 会给每个页面上识别到的字段打状态——`ready`（档案有值）/ `empty`（认得出字段、但档案里没数据）/ `manual`（文件、验证码这类只能手填）/ `unknown`（没匹配到字段词典）。结果卡里的 N 就是 `empty` 的数量，清单里用的是字段词典里的中文名（如「期望城市」「可到岗时间」），正好对应「简历填写」页的栏目，点「去完善简历」补齐后回到原页面重新识别即可一起填上。

#### 3.6.1 悬浮球：为什么之前会消失，现在怎么做到常驻

**现象**：在 `akr.jobs.feishu.cn`（Moka 系）的网申页上，右下角的悬浮球不见了，但页面上确实有表单，弹窗里也认得 8 个字段。

**原因**：`boot()` 里有一句门槛——

```js
// 旧逻辑：页面有明显网申表单时，才显示浮层（避免打扰普通网页）
var hasForm = items.filter(c => c.field && c.status === 'ready').length >= 3;
if (isTop && hasForm) { ensureUI(); renderPanel(); }
```

它要求「**已匹配到档案的可填字段 ≥ 3 个**」才创建整个浮层。而那个页面的标签是画在独立容器里的（Moka 的常见写法），8 个字段全部落在 `unknown`，`ready = 0`，于是 `ensureUI()` 根本没被调用——**不是球被隐藏了，是整套浮层压根没建出来**。而 `boot()` 只在页面加载时跑一次，之后无论表单怎么变都不会再补。

另外还有两个次要漏洞：

- `startPick()` 先 `display:none` 再去找遮罩层，一旦中途退出（换路由、切标签页、pointercancel），`stopPick()` 没机会执行，球就永久停在隐藏态。
- 浮层节点挂在 `documentElement` 上，但没人管它是否还在——SPA 清 DOM 或框架挪节点后，节点没了也不会重建。

**现在的显隐规则**（唯一真值：不让球自己消失）：

| 场景 | 球的可见性 | 触发条件 |
|------|-----------|----------|
| 任意 http/https 页面（顶层 frame） | **显示** | 脚本一注入就 `mountUI()`，不再看有没有表单 |
| 页面上没有表单 / 字段全没认出来 | **显示**，角标写「无表单」或「0/N」并降透明度到 80% | `updateBubbleState()` |
| 识别到可填字段 | **显示**，角标「可填 / 总数」 | `refreshReport()` → `updateBubbleState()` |
| 面板展开 / 收起 | **显示**（面板定位避开球） | 点球 toggle；拖过的球会自动上/下翻转面板 |
| 选区填写进行中 | **临时隐藏** | `startPick()` 置 `bubbleHidden = true` |
| 退出选区（松手 / `Esc` / `pointercancel` / 中断） | **恢复** | `stopPick()` 清 `bubbleHidden` 并复位 `display` |
| 页面删掉浮层节点 / 挪走 / 用 CSS 隐藏 | **1.2s 内自愈** | `keepBubble()` 看门狗 |
| 切回标签页、前进后退、hash 路由变化、窗口缩放 | **立即自愈** | `pageshow` / `focus` / `popstate` / `hashchange` / `visibilitychange` / `resize` |
| iframe 内 | 不显示 | `isTop` 守卫，避免每个框架都长一个球 |

**常驻的实现**（都在 `content/content.js`）：

```js
function keepBubble() {                  // 1.2s 一次 + 事件触发
  var u = mountUI();                     // 节点被删/被挪 → appendChild 回来
  if (pickActive) return;                // 选区进行中，尊重这一次隐藏
  bubbleHidden = false;
  if (b.style.display === 'none') b.style.display = '';   // 被藏了 → 放出来
  if (cs.display === 'none' || cs.visibility === 'hidden') // 被页面样式干掉 → !important 顶回去
    b.style.setProperty('display', 'flex', 'important');
}
```

配套的三处硬约束：

1. **`boot()` 不再有 `hasForm` 门槛**：先 `mountUI()` 把球挂上，识别结果异步补到角标里；面板内容为空时给「这个页面没有识别到网申表单」的引导卡，而不是一片 0%。
2. **`bubbleHidden` 是唯一的隐藏开关**，只在 `startPick()` 里置真，`stopPick()` 与看门狗都会把它清掉——不存在"忘了恢复"的分支。
3. **浮层不吃页面事件**：host 设 `pointer-events:none`，只有 `.bubble / .panel / .pick` 自己 `pointer-events:auto`，所以它铺在页面上也不会挡住提交按钮。

**顺手加的两件事**：

- **可拖动 + 记住位置**（`offerpilot.bubble.v1`）：拖到不挡「提交简历」的地方，刷新后还在原位；面板会跟着球走，空间不够时自动压高度（面板内部滚动）或翻到球下方，**不会盖住球**。
- **拖动不算点击**：`dragMoved` 标记把拖完那次 `click` 吃掉，不会误开面板。

### 3.7 岗位自动匹配 + 三类填写（第 5 轮新增）

**先说结论**：插件不再"永远用默认那份简历"。打开招聘页 → 读出这是哪个岗位 → 在简历库里挑出最贴的那一版 → 用这一版去填。匹配、填写、复制三条链路共用同一个纯逻辑模块 `assets/js/resumematch.js`（页面、content script、Service Worker 三处都加载），所以浮窗、工作台、弹窗给出的结论不会互相打架。

#### 3.7.1 匹配算法：四步、可解释

| 步骤 | 做什么 | 实现要点 |
|------|--------|----------|
| ① 抽岗位 | `extractJob({title, host, h1, subtitle, text})` | 优先级：带标签的行（`应聘岗位：`/`职位名称：`/`投递职位：`）→ `h1` 与 `.job-title`/`jobName`/`positionName`/`postTitle` → `og:title` → `<title>` 里 `- XXX` 的后缀 → 正文前 40 行里的短行。`章节标题`（如"岗位职责"）用 `NOT_ROLE` 挡掉，不会被当成岗位名 |
| ② 判方向 | 岗位文本落到 11 个方向之一（可命中两个） | 数据分析 / 后端 / 前端 / 算法 / 产品 / 运营 / 测试 / 设计 / 销售 / 人力 / 财务，每个方向一张关键词表；取命中最多的两个方向，第二个按 **0.5 权重**参与打分 |
| ③ 给版本打分 | `scoreResume(resume, job, profile)` | 基础 44 分；方向命中：第一方向 +40、第二方向 +20（×0.5）；标签命中 +4/个（上限 14）；主打经历标签 +2/个（上限 6）；版本名称直接命中岗位名 +10；默认版本 +2；最后钳到 **28–96** |
| ④ 排序取最优 | `rank(resumes, job, profile)` | 返回 `{best, list, job, unanswered, reason}`；分数降序，`best` 即本次使用版本 |

匹配度分档（面板与工作台用同一套措辞）：**≥85 高匹配** / **70–84 可用** / **55–69 一般，建议核对** / **<55 低匹配，已提示换一份**。

> **一个刻意的取舍**：版本定位只读 `名称 / 目标岗位 / 标签 / 概述`，**不读经历**。因为同一份档案里所有版本共用同一批经历，把经历算进去会让每个版本都命中"数据分析"，分数被拉平成 96/96/96——反而失去区分度。测试里专门锁了这条（`resume-match.test.js` 的"版本排序"组）。

抽不到岗位信号时**不猜**：退回默认版本，`unanswered = true`，面板明写「没识别到岗位，先按默认简历填写」，工作台同样提示。

#### 3.7.2 三类填写：行为预期逐条写清

| 方式 | 入口属性 | 具体行为 | 你会看到 |
|------|----------|----------|----------|
| **一键填写** | `data-fill="empty"` | 扫全页 → 只处理空白字段 → 按**当前匹配版本**取值（经历的先后顺序、自我评价文案都来自该版本）→ 写入并派发事件 → 回读校验 → 还原滚动位置 | 绿色结果卡「填写完成，已写入 N 个字段 · 预计省 X 分钟」；下方琥珀色「N 项因简历无对应数据未填」 |
| **选区填写** | `data-pick-start` | 铺全屏 `.pick` 遮罩（蓝色蒙层 + 内描边），`pointerdown/move/up` 画框，`Esc` 退出；用矩形与 `getBoundingClientRect()` 求交，**只写相交的字段**；框小于 24×24 视为误触 | 遮罩消失、toast「已填写框选区域」；结果卡标题带「（框选区域 · N 个字段）」，不会把"没框到的字段"算成缺失 |
| **辅助填写** | `data-assist` | 逐条列出 `empty` 字段，按字段类型就地生成草稿（时间/数字/选项按字段词典格式化，文本类用版本里的相关经历拼），**纯本地、不联网**；`验证码/校验码/短信码/图形码/密码` 一律不出现 | 每行一个可编辑文本框 + 「填入这项」，底部「全部填入」；填完该项从列表消失 |

三者共用同一个写入器与撤销栈：任何一种方式填的内容都能被「撤销填写」一次性回滚，也都受"不覆盖已有内容、不动文件框、不点提交"三条硬约束。

#### 3.7.3 简历导航：点一下就是全文

工作台浮窗与页面浮窗里的「简历」区都是**导航列表**，每行 = 版本名 + 目标岗位 + 匹配分 + 两个图标：

- **点版本名**（`data-copy-resume`）→ 把该版本简历的**完整纯文本**写进剪贴板，toast 报「已复制《…》· N 字」。文本顺序：姓名/联系方式 →【自我评价】→【教育背景】→ 实习/项目/校园经历（按该版本排序，每条带起止时间）→【专业技能】…
- **点 `›`**（`data-flash`）→ 面板切成「简历闪填」宽版：左侧版本导航，右侧按栏目分组的字段 chip；点任一 chip 复制该字段值，右上「复制全部」复制整份。
- 工作台浮窗同一列表的两个动作分别是 `⧉`（复制）与 `✓`（本次改用这个版本）。

复制走 `navigator.clipboard.writeText`，在无权限/非安全上下文下退到隐藏 `textarea` + `execCommand('copy')`，两条路都失败才提示"请手动全选复制"，不静默失败。

#### 3.7.4 版本一致性：不只换名字，换的是内容

选中的版本会一路贯穿到取值层，不是只换标题：

- `fieldschema.resolve(state, field, resume)` / `Store.resolveField(field, resume)` 接收当前版本；
- 经历类字段按 `resume.order` 重排，首选「主打经历」；
- `自我评价` 直接取该版本的 `summary`；
- 网申页头部显示「本次使用《简历 · 后端开发》填写」并提供「换一份」。

端到端验证过：选「简历 · 后端开发」后一键填写，自我评价变成该版本的概述，项目经历第一条是 `校园二手交易平台「海淘集」｜后端负责人 … 2025.09 - 2026.01`，而不是默认版本的数据分析项目。

#### 3.7.5 在投递页就地切换简历（本轮修复）

之前切换简历要「换一份 → 闪填 → 返回」，比参考产品多两步，且面板在没读到档案时只显示占位文案，看起来像卡住。现在的链路压成一步：

```
打开招聘页 → 面板顶部「当前简历」→ 点开列表 → 点某一版
        → 立即重算可填字段 → 绿色「已切换成功」+「立即填写」→ 一键填写用这一版
```

三处配套改动：

1. **面板自带选择器**：不再依赖闪填视图。列表就四样信息——版本名、目标岗位、匹配分（<58% 用琥珀色）、是否「当前使用」，点一行即生效，不需要二次确认。
2. **选择会记住**：写进 `chrome.storage.local` 的 `offerpilot.pick.v1`，刷新页面、切到别的招聘站仍是这一版；同时 `matchInfo` 会把它报给弹窗与工作台，三处口径一致。
3. **不再有"加载态"**：面板打开时先用缓存把界面画出来，再异步刷新识别结果；没档案就显示「还没读到你的简历档案 → 打开简历库」，而不是一句「正在识别…」。

**为什么之前"填不动"**：真实投递页（Moka / 北森）的「性别」「招聘信息来源」等字段是多层 `div` 拼出来的自定义下拉，内核是 `readonly` input。旧逻辑 `if (el.readOnly) continue` 会把它们整片跳过——识别率看起来还行，但那几个必填项永远填不上。现在按 §3.2 的 `selectx` 流程处理，实测在模拟 Moka 页面上「招聘信息来源」能选中「校园招聘官网」，识别率从 5/6 提到 6/6。

#### 3.8.2 业务流程

```
① 建档：上传简历 PDF → 档案（已有）
② 选岗：岗位大厅筛选 → 看匹配度 → 收藏 / 勾选
③ 建任务：批量投递 → 任务进入队列（queued，不限次数）
④ 执行：后台逐个开标签页 → 等加载 → 内容脚本识别 + 填写
⑤ 收尾：填完 → 有缺项就「等你回复」，没有就「填写完成」
⑥ 你处理：回问题（自动回填）/ 接管页面 / 核对后自己点提交
⑦ 复盘：投递进度看板 + 岗位情报
```

#### 3.8.3 任务状态机

| 状态 | 含义 | 谁会推进它 |
|------|------|-----------|
| `queued` | 排队中 | 创建任务 / 重试 |
| `opening` | 正在打开招聘官网 | 后台 `openTask()` |
| `filling` | 页面已加载，正在识别与写入 | 内容脚本回报 `OP_FILL_DONE` 前 |
| `need_input` | 档案里没有的字段，暂停等确认 | 后台收到缺失清单 |
| `done` | 填写完成，停在页面等你核对提交 | 后台收到完成回报 |
| `failed` | 打开失败 / 超时 / 无响应 | 70 秒无回报、页面加载超时、无链接 |
| `closed` | 手动关闭 | 用户 |

进度条不是假的：`start 8% → loaded 26% → report 62% → filled 78% → need 84% → finish 100%`，每一步都由真实事件触发（见 `queue.js` 的 `apply()`）。

#### 3.8.4 岗位大厅怎么算匹配度

复用 §3.7 的版本匹配引擎，不另造一套：

```js
ResumeMatch.rank(resumes, {
  company, role,
  text: 岗位职责 + 任职要求 + 标签,
  dirs: ResumeMatch.dirsOf(role + text)   // 岗位方向向量
}, profile)
```

- 返回的 `best` 既是**匹配分**，也是**该岗位该用哪份简历**——建任务时一并写入 `resumeId`，执行时内容脚本直接用这一版，不需要再问；
- 结果按岗位 id + 简历库签名缓存，40 个岗位整页渲染约 **12ms**（实测），滚动不卡；
- 匹配分 <62 用琥珀色标出来，避免"看着都差不多"。

#### 3.8.5 批量执行是怎么跑起来的

全链路只有 5 条消息，都在 `background.js` 的消息中枢里：

| 消息 | 方向 | 作用 |
|------|------|------|
| `OP_QUEUE_RUN` | 工作台 → 后台 | 取最早创建的 queued 任务，开始串行执行 |
| `OP_FILL`（`silent:true`） | 后台 → 内容脚本 | 页面加载完后静默填写，不弹结果卡 |
| `OP_FILL_DONE` | 内容脚本 → 后台 | 回报 `filled / total / missing / report`，后台据此判定 done 或 need_input |
| `OP_ANSWERS` | 工作台 → 后台 → 内容脚本 | 把用户补充的字段值写进页面，写完再回报一次 |
| `OP_FOCUS_TAB` | 工作台 → 后台 | 接管：切到该任务的标签页并聚焦窗口 |

几个必须处理的细节：

1. **等页面真的渲染完**：`chrome.tabs.onUpdated` 的 `complete` 之后还要再等 700ms，否则 SPA 首屏字段还不在 DOM 里；
2. **防卡死**：单个任务 70 秒没回报就判 `failed` 并继续下一个，不会让整条队列停在那里；
3. **不阻塞队列**：`need_input` 只是记录 + 发通知，队列继续跑下一个任务——参考站也是"暂停提醒但其余继续"；
4. **不重复追问**：已回答的字段从后续缺失清单里剔除，否则会"问 → 填 → 再问"死循环；
5. **状态写回不覆盖**：后台每次改任务都是「读最新 state → 只改这一条 → 写回」，避免把用户正在编辑的档案冲掉。

#### 3.8.6 待确认问答（缺字段闭环）

这是"不乱填"的关键。链路：

```
内容脚本填完 → 收集 status=empty 的字段（必填优先，最多 5 个）
             → 原生 select 顺带读出可选项
             → OP_FILL_DONE 上报
后台         → 任务转 need_input，系统通知
控制台       → 黄色提问卡：有选项就下拉，没有就输入框；必填标 *
你提交       → 写任务 + OP_ANSWERS 发回页面
内容脚本     → 按标签归一化匹配字段 → 写入（下拉走 OptionMap 匹配）→ 再次上报
```

「跳过，先按现有档案填」也留着：不想答就跳过，任务直接完成，缺的字段你在页面上自己补。

#### 3.8.7 完全免费（没有任何额度墙）

- **不限额**：`Queue.quotaOf()` 的 `limit / remain` 恒为 `Infinity`，`consume()` 永远返回成功；
- **只记用量**：`state.quota.used` 记录「今天建了几个任务」，跨天归零，用于控制台展示；超过 60 条操作记录自动截断；
- **没有付费/解锁路径**：代码里不存在邀请码、邀请奖励、会员等级、试用期、次数拦截；原先的「每日 3 次」「邀请 +5 次」「上限 100 人」已全部删除；
- 控制台只保留一条「完全免费 · 不限次数」说明卡 + 「分享给同学」（复制纯文本，不含任何奖励）。

#### 3.8.8 和参考站不一样的地方（别误解）

| 维度 | 锦鲤求职 | 本插件 |
|------|---------|--------|
| 执行位置 | 云端浏览器，关掉电脑也在跑 | **本机标签页**，需要浏览器开着、页面能访问 |
| 并发 | 多任务并行 | **串行**，一次一个（避免十几个标签页同时抢焦点） |
| 岗位来源 | 每天爬企业官网，14 万+ | **内置 40 个演示岗位**（企业官网招聘入口 + JD 摘要）+ 你手动导入的链接；没有爬虫，也不假装有 |
| 验证码 | 部分图形验证码可自动处理 | **不处理**，到登录 / 验证码就停下来叫你接管 |
| 提交 | 最终提交由本人确认 | 同上，且**代码里没有任何点击 submit 的路径** |
| 收费 | 服务端计费 / 免费额度 | **完全免费、不限次数**，无会员、无邀请解锁、无试用期 |

### 3.9 真实站点适配：吉比特 hr.g-bits.com（第 9 轮，v1.4.0）

第一次拿到**真实招聘站**做回归（用户在 hr.g-bits.com 投递时 14 个字段只填上 6 个）。线上抓取表单结构存为
`.workbuddy/tests/fixtures/gbits-delivery.html`，配 `gbits-page.test.js`（28 项断言）复现全部失败再逐个修。
这一轮证明了一件事：**此前的 431 项测试全绿也挡不住真实站点**——因为 mock 页面没写 `type="search"`、
没有 `opacity:0` 的自绘单选、没有 readOnly 日历。

**根因清单（全部线上实测确认）**

| 现象 | 组件 | 根因 | 修复 |
|------|------|------|------|
| 性别勾不上 | antd 自绘 radio | 原生 input `opacity:0` 被 `visible()` 误杀，整组单选不进候选 | 新增 `radioUsable()`：radio/checkbox 按「结构在场」判，外壳可见即算 |
| 学历/学校/意向城市/成绩排名/渠道 5 个下拉全灭 | antd Select | 搜索框 `type="search"` 落在 `SKIP_INPUT` 里，**在 selectx 判定之前**就被跳过 | 跳过规则只对不在任何特殊组件里的输入生效（先判组件再判跳过） |
| 出生年月 / 入校时间 / 学位证时间 | antd 月历（readOnly） | `el.readOnly && !sbox` 直接跳过，没有日历写入路径 | 新增 `datebox` 类 + `writeDateBox()`：点开面板 → 年下拉 → 十年面板 → 年 → 月（中文数字按序取第 N 格）；带输入框的全日历走「输入+Enter」 |
| 意向城市只有 深圳/厦门/不限 | antd Select 短列表 | —— | 选不上就如实报告「下拉里没有」，绝不硬塞 |
| 学校选项要搜才有 | show-search + 远程过滤 | 点开时选项是空的 | `writeSelectBox` 直选失败后往搜索框输入值，等远程过滤再匹配（总超时 2.4s） |
| 籍贯 | antd 级联 | 引擎不认识 cascader；值显示在 `.ant-cascader-picker-label`，`input.value` 恒空 | 新增 `cascader` 类 + `writeCascader()`：逐级点选，「广东茂名」这类不带省/市后缀的写法剥后缀吞前缀也能对上；校验看 label |
| 简历不会自动上传 | `<input type=file>` | 词典标注「脚本无法设置文件框」——**这个认知是错的** | `DataTransfer` 注入 File + 派发 change；档案附件材料里存了简历（≤8MB，新增 `unlimitedStorage` 权限）即自动上传，没存则提示先上传 |
| 残留下拉干扰 | SPA 换页/上次没关干净 | 页面可能同时挂多个「未隐藏」下拉 | `dropdownForBox()` 按几何位置选离触发器最近的；关闭走 mousedown+mouseup+click（antd 只听 mousedown） |

**验证**：`gbits-page.test.js` 28 项全过（识别 12 项 + 写入 12 项 + 结果卡 2 项 + 撤销 2 项）；
写入量从 6 → 15 个字段；旧测试 455 项与真机 e2e 全部保持绿色。

**工作方式沉淀**：以后每攻一个真实站点——
1. 保存页面骨架到 `.workbuddy/tests/fixtures/<站名>-<页面>.html`（含关键 antd 隐藏样式）；
2. 在 `.workbuddy/tests/` 加同名 test，先复现失败再修；
3. 修完在 §3.9 表格里追加一行。fixture 是站点的「快照资产」，站点改版时重抓覆盖即可。

### 3.10 真实站点适配：拼多多校招 careers.pddglobalhr.com（第 10 轮，v1.5.0）

用户登录后现场诊断（Next.js 自建站 + **antd v3 + rocket-select**，字段配置由后端接口下发），

## 四、安装


### Chrome / Edge（手动加载）

1. 打开 `chrome://extensions`（Edge 为 `edge://extensions`）。
2. 打开右上角 **开发者模式**。
3. 点 **加载已解压的扩展程序**，选择本项目根目录（即包含 `manifest.json` 的那一层）。
4. 首次安装会自动打开工作台标签页；建议把图标 **固定到工具栏**（拼图图标 → 图钉）。
5. 首次使用先「简历库 → 上传简历 PDF」：解析结果会直接写入档案并生成版本；投递记录默认是空的，只有你真实提交的网申才会出现在看板。

> 扩展 ID 每次重新加载可能变化，属正常现象；不需要任何账号或后端。

### 纯网页预览（无扩展环境）

`index.html` 可直接双击打开或用静态服务器托管，此时 `bridge.js` 判定为非扩展环境：网申页自动切到**演示表单**模式，其余页面功能完全一致。用于快速看界面，不参与真实填充。

## 六、能力边界（重要）

| 限制 | 原因 | 当前处理 |
|------|------|---------|
| **文件类字段** | 脚本不能弹出系统文件选择框，但可以用 `DataTransfer` 把已保存的附件塞进输入框 | 「我的档案-附件材料」里存了简历/成绩单（≤8MB）就自动上传并触发 change；没存则标记「需手动」并提示先上传 |
| **紧急联系人不由工具填** | 属他人隐私信息 | 识别并标记「需手动」，不写入 |
| **不自动点击提交** | 误提交的代价远高于省一次点击 | 只写内容，提交按钮永远由人点 |
| **富文本编辑器** | 部分是自绘组件，不是 `contenteditable` | 尽力写入，失败如实报告 |
| **虚拟滚动下拉 / 级联组件** | 长列表只渲染可视区那几十项，二级选项要悬停才挂载 | 普通/可搜索（show-search 远程过滤会先输入再选）/级联（省市区逐级点选）已支持（v1.4.0，见 §3.9）；纯虚拟长列表若选项不在 DOM 里则如实报告"下拉里没有匹配项" |
| **单页应用换页** | 路由切换后 DOM 重建 | `MutationObserver` 防抖 1.2s 自动重扫 |
| **小语种站点** | 词典以中英文为主 | 未命中即标「未识别」，不猜 |
| **岗位匹配是关键词级，不是语义级** | 方向词典只有 11 类，写法太偏（如"增长黑客""解决方案顾问"）会落到最近的方向或判不出 | 判不出就用默认版本并明说；面板可随时「换一份」，匹配分低于 55% 会提前警告 |
| **列表页/搜索页识别到的岗位** | 一页多个职位时无唯一答案 | 取页面首个岗位标题，浮层里显示出来供你核对，不对就手动切版本 |
| **远程模型调用** | 主动配置 LLM Key 时，AI 功能会把相关档案片段发往你填的端点 | 不配 Key 则全部本地计算、不联网；Key 只存在本机 `chrome.storage` |
| **批量投递是本机串行，不是云端并发** | 扩展只能操作本机标签页；并行开十几个页面会互相抢焦点、也更容易触发风控 | 一次一个，在后台队列里排队推进；关掉浏览器队列就停（§3.8.8） |
| **内置岗位池是演示数据** | 没有企业官网爬虫，也不该假装有 | 40 个岗位标注为演示（企业官网招聘入口 + JD 摘要），真实岗位用「粘贴链接 / JD」导入，导入的会一起参与筛选与统计 |
| **验证码与登录不代劳** | 破解验证码违反站点规则，也容易把账号搞挂 | 到登录 / 验证码就判失败或停在等你接管，通知里写清原因 |

设计取向很明确：**宁可少填一个字段，不可填错一个字段**。所有"没做"的地方都在界面上说清楚，而不是静默失败。
